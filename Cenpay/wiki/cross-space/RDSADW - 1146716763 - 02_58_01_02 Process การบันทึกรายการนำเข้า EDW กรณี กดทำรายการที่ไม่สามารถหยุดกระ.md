## Objectives

1. Register และบันทึกข้อมูล Stats ของรายการนำเข้า EDW ที่ตาราง [tx_reconcile_stats](http://wiki.thaisamut.co.th/display/RDSADW/tx_reconcile_stats) เป็นรายธุรกรรมผังบัญชี เพื่อใช้ในการตรวจสอบความครบถ้วนและความถูกต้องของข้อมูล Transaction (บน [03_40 หน้าจอตรวจสอบรายการ Oper](http://wiki.thaisamut.co.th/pages/viewpage.action?pageId=1148387712)) ที่ส่งจากระบบต้นทางเข้าระบบ EDW ผ่านการทำรายการจากหน้าจอทำรายการของระบบต้นทาง กรณีที่ไม่สามารถหยุดกระบวนการทำรายการที่ระบบต้นทางได้ โดยยังคงให้มีการส่งข้อมูล Reconcile ทุกครั้งที่มีการกดส่งข้อมูลจากหน้าจอ/หน้าจอซ่อม
2. Register และบันทึกข้อมูล Stats ของรายการนำเข้า EDW ที่ตาราง [tx_reconcile_stats](http://wiki.thaisamut.co.th/display/RDSADW/tx_reconcile_stats) เป็นรายธุรกรรมผังบัญชี เพื่อใช้ในการตรวจสอบความครบถ้วนและความถูกต้องของข้อมูล Transaction (บน [03_40 หน้าจอตรวจสอบรายการ Oper](http://wiki.thaisamut.co.th/pages/viewpage.action?pageId=1148387712)) ที่ส่งจากระบบต้นทางเข้าระบบ EDW ผ่าน Batch 5 นาที ซึ่งไม่จำเป็นต้องหยุดกระบวนการทำรายการที่ระบบต้นทาง โดยมีการปรับกระบวนการกรณีที่ติด Error ให้กำหนด Source Amount เป็นค่าว่าง และไม่ส่งรายการที่ Source Amount เป็นค่าว่างซ้ำอีกในการ run batch ครั้งถัดไป

## Process Overview

1. User กดทำรายการที่หน้าจอทำรายการที่ระบบต้นทาง / Batch 5 นาที เริ่ม run เพื่อกวาดข้อมูลส่ง EDW ตามรอบ
2. ระบบต้นทางเตรียมข้อมูลส่ง EDW
3. สำหรับรายการที่กวาดด้วย Batch 5 นาที/10 นาที: ก่อนทำการส่งข้อมูล Reconcile จะมีการตรวจสอบประวัติการส่งที่ Log Reconcile ของระบบต้นทาง หากพบรายการที่มีคีย์ (Reference No, Event Code) เดียวกันและ Source Amount ไม่มีค่า (เป็น null) (ซึ่งหมายถึงรายการที่เคยส่งไม่สำเร็จและถูกทำเครื่องหมายว่าเป็น Error) Batch ไม่ส่งรายการ Reconcile เพิ่มเติมไปยัง EDW
4. สำหรับรายการที่กดจากหน้าจอ/หน้าจอซ่อม: ทำการส่งข้อมูล Reconcile ทุกครั้งที่มีการกดส่งข้อมูล
5. Batch หรือ Manual Trigger ทำการส่งข้อมูลเข้า Kafka (ขั้นตอนอาจแตกต่างกันไปขึ้นอยู่กับระบบต้นทาง)
6. Batch หรือ Manual Trigger ทำการยิง API เพื่อบันทึกรายการธุรกรรมผังบัญชีที่ตาราง [tx_reconcile_stats](http://wiki.thaisamut.co.th/display/RDSADW/tx_reconcile_stats) โดยหลังจากนั้นตรวจสอบสถานะการยิง API ดังนี้
  - กลุ่มระบบต้นทาง Manual Oper และ CoreUL ธุรกรรม Daily ยิง API [02 WS Update/Insert Transaction ของ Reconcile Stats สำหรับรายการธุรกรรมที่นำเข้า EDW](http://wiki.thaisamut.co.th/pages/viewpage.action?pageId=1145962522)
  - กลุ่มธุรกรรมอื่นๆยิง API [01 WS Register Transaction ของ Reconcile Stats สำหรับรายการธุรกรรมที่นำเข้า EDW](http://wiki.thaisamut.co.th/pages/viewpage.action?pageId=1145962524)
  - กรณีบันทึกรายการธุรกรรมผังบัญชีที่ตาราง tx_reconcile_stats สำเร็จ Batch จะทำการบันทึกข้อมูล Log ของรายการธุรกรรมผังบัญชีที่ระบบต้นทาง พร้อมทั้งระบุสถานะส่งสำเร็จ (TRUE)
  - กรณีบันทึกรายการธุรกรรมผังบัญชีที่ตาราง tx_reconcile_stats ไม่สำเร็จ Batch จะทำการบันทึกข้อมูล Log ของรายการธุรกรรมผังบัญชีที่ระบบต้นทาง พร้อมทั้งระบุสถานะส่งไม่สำเร็จ (FALSE) และดำเนินการอย่างใดอย่างหนึ่งต่อไปนี้ซึ่งหลังจากการดำเนินการอย่างใดอย่างหนึ่งแล้วจะกลับมาตรวจสอบตามเงื่อนไขข้อ 6. อีกครั้ง
    - รอ Job Sync ข้อมูลกวาดข้อมูล (ซ่อม) Reconcile Stats จากตาราง Log ของระบบต้นทางไปตาราง[tx_reconcile_stats](http://wiki.thaisamut.co.th/display/RDSADW/tx_reconcile_stats)ของ EDW ในทุกๆ 2 ชั่วโมง หรือ
    - กด run Batch เพื่อกวาดข้อมูล (ซ่อม) Reconcile Stats จากตาราง Log ของระบบต้นทางไปตาราง[tx_reconcile_stats](http://wiki.thaisamut.co.th/display/RDSADW/tx_reconcile_stats)ของ EDW กรณีที่ต้องการส่งข้อมูล (ซ่อม) ทันที

## Preconditions

1. User ทำรายการ ตรวจสอบ และอนุมัติบนหน้าจอทำรายการที่ระบบต้นทางตามกระบวนการของแต่ละระบบ หรือ Batch 5 นาที/10 นาที เริ่ม run ตามรอบ
2. ระบบต้นทางเตรียมชุดข้อมูลส่งเข้าระบบ EDW

## Process Description

1. หลังจากที่ User กดทำรายการที่หน้าจอทำรายการที่ระบบต้นทาง หรือ Batch 5 นาที เริ่ม run เพื่อกวาดข้อมูลส่ง EDW ตามรอบ ระบบต้นทางจะเตรียมข้อมูลส่ง EDW

      - หากบันทึกรายการธุรกรรมผังบัญชีที่ตาราง [tx_reconcile_stats](http://wiki.thaisamut.co.th/display/RDSADW/tx_reconcile_stats)ไม่สำเร็จ: ให้ทำการบันทึกข้อมูล Log ของรายการธุรกรรมผังบัญชีที่ระบบต้นทาง พร้อมทั้งระบุสถานะการส่ง reconcile_send_status = 'FALSE' หลังจากนั้นจะต้องมีการส่ง (ซ่อม) Reconcile ไปยังตาราง [tx_reconcile_stats](http://wiki.thaisamut.co.th/display/RDSADW/tx_reconcile_stats)โดยดำเนินการอย่างใดอย่างหนึ่งต่อไปนี้:โดยทั้ง 2 กระบวนการจะมีการยิง API Register [tx_reconcile_stats](http://wiki.thaisamut.co.th/display/RDSADW/tx_reconcile_stats) อีกรอบ (ย้อนกระบวนการตามข้อ 2 - 6 ของ Process Overview) การส่งข้อมูลจะเกิดขึ้นทุกครั้งที่มีการกดส่งจากหน้าจอ/หน้าจอซ่อม รวมถึงจากการ run ซ่อม
        - รอ Job Sync ข้อมูลกวาดข้อมูลในทุกๆ 2 ชั่วโมง หรือ
        - ทีม IT Support กด run ซ่อมทันที
3. กำหนดหลักการคำนวณจำนวนเงินระบบต้นทาง (tx_reconcile_stats.source_amount) ที่ Spec [หลักการ Mapping จำนวนเงิน Reconcile ของระบบต้นทาง](http://wiki.thaisamut.co.th/pages/viewpage.action?pageId=1151074599)
4. กำหนด Mapping ระหว่างผังบัญชี และ GL เพื่อคำนวณจำนวนเงินระบบ EDW (tx_adwpc_process_log.edw_reconcile_amount) ที่ตาราง [cf_event_reconcile_formula](http://wiki.thaisamut.co.th/display/RDSADW/cf_event_reconcile_formula)

## Post-conditions

- Register และบันทึกข้อมูล Stats ของรายการนำเข้า EDW ที่ตาราง [tx_reconcile_stats](http://wiki.thaisamut.co.th/display/RDSADW/tx_reconcile_stats) เป็นรายธุรกรรมผังบัญชี สำหรับรายการที่ส่งสำเร็จ สำหรับรายการ Batch ที่ติด Error และถูกทำเครื่องหมายโดยการกำหนด Source Amount เป็นค่าว่าง จะถูกบันทึกในตาราง Log ที่ระบบต้นทางด้วยสถานะ 'FALSE' และ Source Amount ว่าง เพื่อป้องกันการส่งซ้ำ
- นำข้อมูลไปแสดงที่ [หน้าจอตรวจสอบรายการ Oper](http://wiki.thaisamut.co.th/pages/viewpage.action?pageId=1148387712)
