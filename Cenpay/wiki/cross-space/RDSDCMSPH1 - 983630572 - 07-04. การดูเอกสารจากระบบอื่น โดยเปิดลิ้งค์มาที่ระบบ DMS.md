# Overview

ระบบ DMS รองรับการกดวิวเอกสารจากระบบอื่น โดยเป็นการเปิดลิ้งค์มาที่ระบบ DMS
การเปิดลิ้งค์มาที่ระบบ DMS จะมี 4 รูปแบบ ตามตัวอย่างด้านล่าง ดังนี้

- [รูปแบบที่ 2 : การดูเอกสารผ่านหน้าจอสืบค้นข้อมูลเอกสาร ด้วย Subject](#id-07-04.การดูเอกสารจากระบบอื่นโดยเปิดลิ้งค์มาที่ระบบDMS-รูปแบบที่2:การดูเอกสารผ่านหน้าจอสืบค้นข้อมูลเอกสารด้วยSubject)
- [รูปแบบที่ 3 : การดูเอกสารผ่านหน้าจอวิวเอกสาร ด้วย Index key](#id-07-04.การดูเอกสารจากระบบอื่นโดยเปิดลิ้งค์มาที่ระบบDMS-รูปแบบที่3:การดูเอกสารผ่านหน้าจอวิวเอกสารด้วยIndexkey)
- [รูปแบบที่ 4 : การดูเอกสารผ่านหน้าจอวิวเอกสาร ด้วย Reference ID](#id-07-04.การดูเอกสารจากระบบอื่นโดยเปิดลิ้งค์มาที่ระบบDMS-รูปแบบที่4:การดูเอกสารผ่านหน้าจอวิวเอกสารด้วยReferenceID)
** ต้องใช้ nodejsrepo version 1.125 ขึ้นไป
**หมายเหตุ :**
1. **ต้องมีสิทธิ์ view เอกสารกลุ่มนั้นถึงจะสามารถดูหรือค้นหาเอกสารกลุ่มนั้นได้ (ตัวอย่างสิทธิ์วิวเอกสารกลุ่มใบคำขอ = dms:document:newcase)**
2. **ต้องมีสิทธิ์ download **เอกสารกลุ่มนั้นถึงจะสามารถดาวโหลดเอกสารกลุ่มนั้นได้ (**ตัวอย่างสิทธิ์ดาวโหลดเอกสารกลุ่มใบคำขอ = dms:download:newcase)******
3. **URL จะแตกต่างกันไปในแต่ละ Environment ดังนั้นห้าม fix ส่วนที่เป็น domain ในโค้ด โดยตัวอย่างที่ยกมาเป็น URL ของ SIT**
4. **ข้อมูลเพิ่มเติมของฟังก์ชั่น window.open [https://www.w3schools.com/jsref/met_win_open.asp](https://www.w3schools.com/jsref/met_win_open.asp)**
5. **กรณีใช้ OLINewWindow ต้องใช้ nodejsrepo version 1.125 ขึ้นไปเท่านั้น**
**URL NBS Portal ของแต่ละ Environment**

| Environment | URL NBSPORTAL |
|---|---|
| SIT | [https://intranet-api.ochi.link/](https://intranet-api.ochi.link/) |
| UAT | [https://uat.intranet-api.ochi.link/](https://uat.intranet-api.ochi.link/) |
| PRODUCTION | [https://intranet-api.ocean.co.th/](https://intranet-api.ocean.co.th/) |

### รูปแบบที่ 1 : การดูเอกสารผ่านหน้าจอวิวเอกสาร ด้วย Document ID

**1. การดูเอกสารผ่านหน้าจอวิวเอกสาร**
เป็นการเปิดหน้าจอวิวเอกสารของระบบ DMS โดยการระบุ document id (document id จะได้ตอนอัพโหลดเอกสารเข้า DMS. ดูเพิ่มเติมที่ service [uploadDocument](/display/RDSDCMSPH1/uploadDocument))
รองรับการวิวเอกสารเวอร์ชันล่าสุดเท่านั้น ไม่สามารถวิวเอกสารเวอร์ชันที่ไม่ใช่ล่าสุดได้ แต่สามารถดาวโหลดเวอร์ชั่นก่อนหน้าได้ที่ส่วนเวอร์ชันก่อนหน้า

### รูปแบบที่ 2 : การดูเอกสารผ่านหน้าจอสืบค้นข้อมูลเอกสาร ด้วย Subject

**2. การดูเอกสารผ่านหน้าจอสืบค้นข้อมูลเอกสาร**
เป็นการเปิดหน้าจอสืบค้นข้อมูลเอกสารของ DMS พร้อมกับระบุ หัวข้อค้นหา และ ข้อมูลตามหัวข้อค้นหา ระบบจะทำการค้นหาเอกสารให้โดยอัตโนมัติ จากนั้นจึงเลือกเอกสารที่ต้องการดู
ตัวอย่างการค้นหาโดยระบุ หัวข้อค้นหา = "เลขที่ใบคำขอ" , ข้อมูลตามหัวข้อค้นหา = "5394709"
โดย subject ให้ระบุเป็น index_code ของตาราง [index_master](/display/RDSDCMSPH1/index_master) เช่น PROPOSAL_NO , ส่วน detail คือ value ที่ต้องการค้นหา เช่น 5394709

### รูปแบบที่ 3 : การดูเอกสารผ่านหน้าจอวิวเอกสาร ด้วย Index key

**3. การดูเอกสารผ่านหน้าจอวิวเอกสาร ด้วย Index key ของแต่ละประเภทเอกสาร**
เป็นการเปิดหน้าจอวิวเอกสารของระบบ DMS โดยอัตโนมัติ โดยต้องระบุค่า ดังนี้

| **Name** | **Type** | **Require** | **Description** | **Example** | **Validation** |
|---|---|---|---|---|---|
| documentType | String | Y | รหัสประเภทเอกสาร | NEW_UW_CO | case sensitive และต้องมีข้อมูลในตาราง document_type (ดูคอลัมน์ [รหัสสำหรับอ้างอิงข้อมูลประเภทเอกสาร](/pages/viewpage.action?pageId=806420784)) |
| index1 | String | Y | Index Key เอกสารลำดับที่ 1 | PROPOSAL_NO | key ต้องตรงกับตาราง document_type_index และต้องส่งมาครบตาม index key ที่ config ไว้ (ดูจาก index_key_flag = 'Y')โดยค่า indexKey ที่ส่งต้องเป็น indexKey ของประเภทเอกสารเท่านั้น ระบบจะไม่ค้นหาด้วย index ของเอกสาร |
| value1 | String | Y | ค่าของ IndexKey ลำดับที่ 1 | 1001461034 |
| index2 | String | N | Index Key เอกสารลำดับที่ 2 | REFERENCE_NO |
| value2 | String | N | ค่าของ Index Key ลำดับที่2 | 1 |

หมายเหตุ
Icon
- ต้องส่งประเภทเอกสาร (DocumentType) เสมอ
- ต้องส่ง index คู่กับ value ตามเลข running number โดยจะขึ้นอยู่กับ indexKey ของประเภทเอกสารว่ามีกี่คีย์
