# Objectives

- `เพื่ออัปเดตสถานะของรายการ Transaction ที่เกินอายุการรับเงินผ่านช่องทางเช็ค โดยอัตโนมัติ`
- `เพื่อให้ข้อมูลสถานะในระบบ Payment Management มีความถูกต้องและสอดคล้องกับระบบที่เกี่ยวข้อง`

# Process Overview

- Batch Process นี้จะทำงานทุกวัน เวลา 22.30 น. เพื่อกวาดรายการ Transaction ที่ยังคงมีสถานะ "เช็ครอขึ้นเงิน" เกินจำนวน ครบ 181 วัน
- Batch Process นี้จะใช้เงื่อนไขในการนับวันที่ออกเช็ค ([tx_payment_detail](/display/RDSCPENH/tx_payment_detail).cheque_issue_date) วันที่จ่ายจริง ([tx_batch_payment](/display/RDSCPENH/tx_batch_payment).paid_date) CPENH Ph1 #[61834](https://redmine.ochi.link/issues/61834) Edited by jitin.kh 30/03/2569 เป็นวันที่ T และนับไป 180 วัน (180 วัน : นับรวมวันหยุด) โดยในวันที่ T+180 = 181 จะใช้เป็นวันที่เปลี่ยนสถานะรายการ "เช็ครอขึ้นเงิน" เปลี่ยนเป็น "เช็คหมดอายุ"
----------------------------------------------------------------------------------------------------------------- *Ph1R2 + New Loan Ph1*
- Batch Process นี้จะทำงานทุกวัน เวลา 22.30 น. เพื่อกวาดรายการ Transaction ที่ยังคงมีสถานะ "เช็ครอขึ้นเงิน" เกินจำนวน cheque_expired วัน
- Batch Process นี้จะใช้เงื่อนไขในการนับวันที่ออกเช็ค ([tx_payment_detail](/display/RDSCPENH/tx_payment_detail).cheque_issue_date) วันที่จ่ายจริง ([tx_batch_payment](/display/RDSCPENH/tx_batch_payment).paid_date) เป็นวันที่ T และนับไป [cf_bank_account_mapping_data](/display/RDSCPENH/cf_bank_account_mapping_data).cheque_expired วัน (cheque_expired วัน : นับรวมวันหยุด) โดยในวันที่ T + cheque_expired = วันที่เปลี่ยนสถานะรายการ "เช็ครอขึ้นเงิน" เปลี่ยนเป็น "เช็คหมดอายุ" *ตัวอย่าง [cf_bank_account_mapping_data](/display/RDSCPENH/cf_bank_account_mapping_data).payment_channel_type = 'CHEQUE_BANK' and cheque_expired = '380' ดังนั้น T + 380 = วันที่ 381 จะใช้เป็นวันที่เปลี่ยนสถานะรายการ "เช็ครอขึ้นเงิน" เปลี่ยนเป็น "เช็คหมดอายุ"*

# Post-conditions & Error Handling

- `Post-conditions (Success):`
  - รายการ Transaction ใน lg_payment_detail ที่เคยมีสถานะเป็น 'เช็ครอขึ้นเงิน' จะถูกอัปเดตเป็นสถานะ 'เช็คหมดอายุ'
  - ระบบบันทึก Log การทำงานของ Batch Process สำเร็จ
- `Post-conditions (Failure) & Error Handling:`
  - `กรณีเรียก Web Service ไม่สำเร็จ (e.g., Timeout, Connection Error):`
    - Action: ระบบจะบันทึก Log ข้อผิดพลาดพร้อมระบุ id ของรายการที่ไม่สำเร็จ, ข้ามการอัปเดตสำหรับรายการนั้น และดำเนินการกับรายการถัดไป
    - Notification: หากเกิดข้อผิดพลาดติดต่อกันเกิน 3 ครั้ง, ระบบจะส่งแจ้งเตือนไปยัง System Admin
  - `กรณี Database Update ไม่สำเร็จ:`
    - Action: ระบบจะพยายาม Rollback การเปลี่ยนแปลงสำหรับรายการนั้น และบันทึก Log ข้อผิดพลาดร้ายแรง
    - Notification: ระบบจะส่งแจ้งเตือนไปยัง System Admin ทันที
  - `กรณีได้รับสถานะจาก EDW ที่ไม่รู้จัก (ไม่อยู่ใน image.png):`
    - `Action: ระบบจะไม่ทำการอัปเดต, บันทึก Log เป็น Warning พร้อมระบุ id และค่าสถานะที่ไม่รู้จัก`
    - `Notification: ไม่มีการแจ้งเตือน แต่ต้องมีการ Monitor Log ดังกล่าวเป็นประจำ`
