# Objectives

- `เพื่ออัปเดตสถานะประมวลผลไฟล์ SUN ของรายการ Transaction ที่หน้าจออนุมัติจ่ายและบันทึกบัญชี ([tx_payment_dashboard](/display/RDSCPENH/tx_payment_dashboard)) ให้เป็นปัจจุบันตรงตามสถานะที่ประมวลผลในระบบ EDW โดยอัตโนมัติ`
- `เพื่อให้ข้อมูลสถานะในระบบ Payment Management มีความถูกต้องและสอดคล้องกับระบบที่เกี่ยวข้อง`

# Process Overview

- `Batch Process นี้จะทำงานทุกๆ 5 นาที เพื่อกวาดรายการ Transaction ที่ผ่านการอนุมัติจ่ายแล้ว (`voucher_status` เป็น 'ARR' 'APR' Edited by jitin.kh 30/01/69 หรือ 'APP') แต่สถานะการประมวลผลไฟล์ SUN (`account_status`) ยังไม่เสร็จสมบูรณ์ (เป็นค่าว่าง หรือไม่ใช่ 'SUCCESS' หรือ 'EDW_POSTING') จากนั้น Batch จะเรียก Web Service [WS สำหรับดึง SUN Status กลับไป Stamp ระบบต้นทาง](/pages/viewpage.action?pageId=1284571237) ของระบบ EDW เพื่อสอบถามสถานะล่าสุด และนำมาตีความก่อนอัปเดตลงในตาราง `tx_payment_dashboard` เฉพาะในกรณีที่สถานะมีการเปลี่ยนแปลง`

# Pre-conditions

- `ต้องมีรายการ Transaction ในตาราง `tx_payment_dashboard` ที่มีเงื่อนไขดังนี้:`
  - ``voucher_status` เป็น 'ARR' 'APR' (อนุมัติ)` Edited by jitin.kh 30/01/69 หรือ 'APP' (อนุมัติจ่ายเงิน)
  - `และ `account_status` เป็นค่าว่าง (NULL) หรือมีค่าอื่นที่ไม่ใช่ 'SUCCESS' และ 'EDW_POSTING'`
- `Batch สามารถเชื่อมต่อกับฐานข้อมูลของระบบ Payment Management และสามารถเรียกใช้งาน Web Service ของ EDW ได้`

# Process Description

1. `Batch กวาดข้อมูล Transaction ที่รอการอัปเดต`
  - Actor: Batch Process (System)
  - Action: Query ข้อมูลจากตาราง `tx_payment_dashboard` เพื่อค้นหารายการตามเงื่อนไขที่กำหนด
  - System: Payment Management
  - Data Involved: `id`, `fin_reference_no`, `account_status`
  - ตัวอย่าง SQL Statement ดึงข้อมูล: <![CDATA[SELECT id, fin_reference_no, account_status FROM tx_payment_dashboard WHERE voucher_status IN (&#39;APR&#39;, &#39;APP&#39;) -- Replace &#39;ARR&#39; with &#39;APR&#39; Edited by jitin.kh 30/01/69 AND (account_status IS NULL OR account_status NOT IN (&#39;SUCCESS&#39;, &#39;EDW_POSTING&#39;));]]>
2. `เรียก [WS สำหรับดึง SUN Status กลับไป Stamp ระบบต้นทาง](/pages/viewpage.action?pageId=1284571237) เพื่อสอบถามสถานะจาก EDW`
  - `Actor: Batch Process (System)`
  - `Action: รวบรวม `fin_reference_no` ทั้งหมดที่ได้จากขั้นตอนที่ 1, แบ่งเป็นกลุ่ม (chunk) ขนาดไม่เกิน 20 รายการ และเรียก Web Service สำหรับแต่ละกลุ่ม`
  - `System: API Gateway / EDW`
  - `Input Body: เป็น JSON Array ของ `referenceNumber```Parameter Name``Description``Source Value (from tx_payment_dashboard)``referenceNumber``เลขที่อ้างอิงฝ่ายการเงิน``fin_reference_no`
3. `รับสถานะ SUN จาก EDW`
  - `Actor: Batch Process (System)`
  - `Action: ระบบรับผลลัพธ์ (JSON Array) จาก Web Service และสำหรับแต่ละรายการในผลลัพธ์ จะใช้ค่า `sunStatus` ที่ได้รับมาโดยตรง`
  - `System: Payment Management`
  - `Data Involved: `referenceNumber`, `sunStatus` (จาก WS)`
4. Decision Point: ตรวจสอบการเปลี่ยนแปลงของสถานะ
  - Action: สำหรับแต่ละ `referenceNumber` ที่ได้รับจาก`Web Service,` ระบบจะเปรียบเทียบค่า `sunStatus` ที่ได้รับมากับสถานะปัจจุบัน (`account_status`) ของรายการนั้นในฐานข้อมูล
    - หาก `sunStatus` *ไม่เท่ากับ* `account_status`:
      - ดำเนินการต่อใน ขั้นตอนที่ 5 เพื่ออัปเดตข้อมูล
    - หาก `sunStatus` *เท่ากับ* `account_status`:
      - ข้ามการอัปเดตสำหรับรายการนี้ และไปทำรายการถัดไป
5. `อัปเดตสถานะในตาราง `tx_payment_dashboard```Actor: Batch Process (System)``Action: อัปเดตฟิลด์ `account_status` ในตาราง `tx_payment_dashboard` ด้วยค่า `sunStatus` ที่ได้รับจาก Web Service โดยตรง``System: Payment Management DB``Data Involved: `fin_reference_no`, `sunStatus```ตัวอย่าง SQL Statement อัปเดตข้อมูล:` <![CDATA[UPDATE tx_payment_dashboard SET account_status = :sun_status_from_ws, -- ค่า sunStatus ที่ได้จาก WS โดยตรง updated_date = CURRENT_TIMESTAMP, updated_by = &#39;SYSTEM_BATCH&#39; WHERE fin_reference_no = :reference_no;]]>

# Post-conditions & Error Handling

- `Post-conditions (Success):`
  - `รายการ Transaction ใน `tx_payment_dashboard` ที่เข้าเงื่อนไข จะถูกอัปเดต `account_status` เป็นสถานะล่าสุดจากระบบ EDW (หากมีการเปลี่ยนแปลง)`
  - `ระบบบันทึก Log การทำงานของ Batch Process สำเร็จ`
- `Post-conditions (Failure) & Error Handling:`
  - กรณีเรียก`Web Service ไม่สำเร็จ (e.g., HTTP 5xx, Timeout):`
    - `Action`: ระบบจะบันทึก `Log` ข้อผิดพลาดของทั้งกลุ่ม (chunk) ที่เรียกไม่สำเร็จ และข้ามไปทำงานกลุ่มถัดไป
  - กรณี Web Service ตอบกลับแต่ไม่พบข้อมูลของ `referenceNumber` ที่ส่งไป:
    - Action: ระบบจะบันทึก Log เป็น Warning ว่าไม่พบข้อมูลสำหรับ `referenceNumber` นั้นๆ และข้ามไป
  - `กรณี Database Update ไม่สำเร็จ:`
    - `Action: ระบบจะพยายาม Rollback การเปลี่ยนแปลงสำหรับรายการนั้น และบันทึก Log ข้อผิดพลาดร้ายแรง`
