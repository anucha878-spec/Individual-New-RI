## Screen Overview

### วัตถุประสงค์ (Objective)

เพื่อให้ฝ่ายปฏิบัติการค้นหา ตรวจสอบ และยืนยัน/ยกเลิกรอบการออกจดหมายแจ้งโอนเงินผลประโยชน์ล่วงหน้า (LB03) ที่ Batch เตรียมข้อมูลไว้แล้ว ก่อนส่งเข้าสู่กระบวนการ Generate เอกสาร/จัดเก็บ DMS/ส่งต่อให้ EMN จริง (human-in-the-loop workflow ที่ไม่มีในระบบเดิม)

### ผู้ใช้งาน (Target Users)

เจ้าหน้าที่ฝ่ายปฏิบัติการ (Operations) ของทีมงาน Centralized Payment ที่มีสิทธิ์เข้าถึงเมนู "จดหมายแจ้งโอนเงินผลประโยชน์ล่วงหน้า"

### เงื่อนไขก่อนการทำงาน (Pre-Condition)

- Batch #1 (ฝั่ง Cenpay) ได้ประมวลผลและเตรียมข้อมูล Header/Detail ไว้ในตาราง `tx_letter_summary` / `TX_LETTER_DETAIL` แล้วอย่างน้อย 1 รอบ (ดึงจาก AS400 `OLIS_OLPLTBNF` และ Irisapp `Temp_LD02_LD03` พร้อมกัน)
- ผู้ใช้ผ่านการยืนยันตัวตนและมีสิทธิ์การใช้งานเมนูนี้แล้ว

### การกระทำกับหน้าจอ (Actions)

- ระบุเงื่อนไขค้นหาอย่างน้อย 1 เงื่อนไข (ปี/เดือนที่ประมวลผล, ปี/เดือนรอบการแจ้งรับเงิน, หรือสถานะ) แล้วกด "ค้นหา"
- กด "ล้างเงื่อนไข" เพื่อล้างค่าฟอร์มค้นหาทั้งหมด
- กด "ยืนยัน" ที่แถวซึ่งสถานะ = `รอยืนยันสร้างจดหมาย` → เปิด popup สรุปข้อมูล → กด "ยืนยัน" ซ้ำใน popup เพื่อยืนยันจริง
- กด "ยกเลิก" ที่แถวซึ่งสถานะ = `รอยืนยันสร้างจดหมาย` → เปิด popup → กด "ยืนยัน" ใน popup เพื่อยกเลิกรายการ
- กด "ดูรายละเอียด" เพื่อเข้าสู่หน้าจอ Detail (FR-03) ของ Header แถวนั้น

### เงื่อนไขหลังการทำงาน (Post-Condition)

- **กรณียืนยัน**: สถานะ Header เปลี่ยนจาก `รอยืนยันสร้างจดหมาย` เป็น `รอส่งจดหมาย`, บันทึก `confirmed_date` และ `confirmed_by`, ระบบเริ่มกระบวนการ Generate PDF/Barcode/จัดเก็บ DMS และเตรียมข้อมูลให้ EMN ดึงไปส่ง Vendor
- **กรณียกเลิก**: สถานะเปลี่ยนเป็น `ยกเลิก`, บันทึก `cancelled_date` และผู้ดำเนินการ
- เมื่อ EMN แจ้งผลสำเร็จกลับผ่าน Service API (FR-09) สถานะเปลี่ยนเป็น `ส่งสำเร็จ` โดยอัตโนมัติ (ไม่ต้องมีการกระทำเพิ่มจากผู้ใช้)

### การจัดการข้อผิดพลาด (Exceptional Handling)

- ไม่ระบุเงื่อนไขค้นหาเลยแล้วกด "ค้นหา" → แสดง Popup Message "กรุณาระบุอย่างน้อย 1 เงื่อนไข" ไม่ query ข้อมูล
- ระบุ "ตั้งแต่" มากกว่า "ถึง" ในช่วงปี/เดือน → แสดง error ให้แก้ไขก่อนค้นหา
- ค้นหาแล้วไม่พบข้อมูล → แสดงข้อความ "ไม่พบรายการที่ตรงกับเงื่อนไข" (ไม่ error)
- ดึงข้อมูลจาก AS400/Irisapp ไม่สำเร็จตอน Batch เตรียมข้อมูล (connection/timeout) → **[TBD]** retry/แจ้งเตือน — ยังไม่ยืนยันจาก BA
- ข้อมูลกรมธรรม์ไม่ครบ (เช่น ไม่มีที่อยู่จัดส่ง) → **[TBD]** ต้อง flag รายการไม่ให้ยืนยันได้จนกว่าจะแก้ไข

## หมายเหตุ / Open Items

- อ้างอิงจาก REQ-pension-letter.md (feature_id: CP-LTR-001) — FR-02a (หน้าจอหลัก LB03) และ FR-05a (กลไกยืนยันรายการ LB03)
- ยังไม่ยืนยัน: retry/แจ้งเตือนเมื่อดึงข้อมูลจาก AS400/Irisapp ไม่สำเร็จ, logic ป้องกันข้อมูลซ้ำกับรอบก่อนหน้าแบบละเอียด
- รูปแบบหน้าจอ/field ในหน้านี้เป็นฉบับร่างจาก Requirement เท่านั้น ยังไม่ได้อ้างอิง Data Source/API จริงแบบละเอียดเหมือนหน้าจออื่นในระบบ (เช่น cf_list_of_value, mastersetting API) — ต้องเติมภายหลังเมื่อยืนยัน backend design
