## Objectives

- เพื่อบันทึกรายการ หักเบี้ยประกันภัยค้างชำระ
- เพิ่อบันทึกรายการ ชำระเบี้ยกรมธรรม์อื่น
- เพื่อบันทึกรายการ ทำประกันเคสใหม่

## Preconditions

- ข้อมูลของรายการจ่ายจะต้องเข้าเงื่อนไขอย่างน้อย 1 ใน 3 ตามเงื่อนไขต่อไปนี้
  - มียอดเงิน**หักเบี้ยประกันภัยค้างชำระ** ( [tx_payment_benefit_expense](http://wiki.thaisamut.co.th/display/RDSCPENH/tx_payment_benefit_expense).overdue_prem_amount > 0 ) และต้องเป็นรายการจ่ายครั้งแรก ( [tx_payment](http://wiki.thaisamut.co.th/display/RDSCPENH/tx_payment).payment_round = 1 )
  - มียอดเงืน**ชำระเบี้ยกรมธรรม์อื่น** ( [tx_payment_benefit_expense](http://wiki.thaisamut.co.th/display/RDSCPENH/tx_payment_benefit_expense).other_policy_prem_amount > 0 ) และต้องเป็นรายการจ่ายครั้งแรก ( [tx_payment](http://wiki.thaisamut.co.th/display/RDSCPENH/tx_payment).payment_round = 1 )
  - มียอดเงิน**ทำประเกินเคสใหม่** ( [tx_payment_benefit_expense](http://wiki.thaisamut.co.th/display/RDSCPENH/tx_payment_benefit_expense).new_policy_prem_amount > 0 ) และต้องเป็นรายการจ่ายครั้งแรก ( [tx_payment](http://wiki.thaisamut.co.th/display/RDSCPENH/tx_payment).payment_round = 1 )

## Objectives

- เพื่อบันทึกรายการ ทำประกันเคสใหม่ ที่ฐานข้อมูลบนระบบรับฝาก
- เพื่อบันทึกรายการ หักเบี้ยประกันภัยค้างชำระ ที่ฐานข้อมูลบนระบบรับฝาก และระบบใบเสร็จส่วนกลาง
- เพื่อบันทึกรายการ ชำระเบี้ยประกันภัยกรมธรรม์อื่น ที่ฐานข้อมูลบนระบบรับฝาก และระบบใบเสร็จส่วนกลาง

## Process Overview

- ตรวจสอบการหักเบี้ยประกันภัยค้างชำระ การลงทะเบียนทำประกันเคสใหม่ และชำระเบี้ยประกันภัยกรมธรรม์อื่น และทำการตั้งรับฝาก และบันทึกข้อมูลที่ Hydra เพื่อออกใบเสร็จที่ระบบใบเสร็จส่วนกลาง
  - overdue_prem_amount > 0
    - สามัญ (เพิ่มการตั้งรับฝากที่ deposit) ดึงข้อมูลใบเสร็จเบี้ยค้างที่ AS/400 group ด้วยงวด แล้วส่ง hydra
    - ไม่ใช่สามัญ (เพิ่มการตั้งรับฝากที่ deposit) ส่ง hydra เดี๋ยว hydra จะไปแยกตามงวดเอง
  - overdue_interest > 0 และไม่มีใบเสร็จที่ tx_receipt
    - สร้างเลขที่ใบเสร็จ tx_receipt ด้วย branch_code และลงสถานะ S
  - ปีต่อปกติ flag register_premium_flag = 1, deposit_id ไม่มีค่า
    - ตั้งรับฝากที่ระบบ Deposit แล้วบันทึกข้อมูลที่ Hydra เพื่อออกใบเสร็จ

## Preconditions

- รายการที่มีการหักเบี้ยประกันภัยค้างชำระ ทำประกันเคสใหม่ และชำระเบี้ยประกันภัยกรมธรรม์อื่น
  - กรณีธุรกรรมผลประโยชน์จ่ายตามเรียกร้อง จะเรียกกระบวนการนี้เพื่อรับคืนหนี้สินเบี้ยทันทีหลังจากทีมบัญชียืนยันตรวจจ่ายบัญชีจาก[หน้าจอรายละเอียด Support Booking](/pages/viewpage.action?pageId=1282507906)
  - กรณีธุรกรรมผลประโยชน์จ่ายตามรอบ ที่ถูกประมวลผลก่อนวันครบรอบการจ่ายเงินผลประโยชน์ จะถูกเรียกกระบวนการนี้จาก Daily Batch เพื่อรับคืนหนี้สินเบี้ยตรงกับวันครบรอบการจ่ายเงิยผลประโยชน์

## Process Description

**1. ตรวจสอบประเภทของรายการและยอดเงิน**
1.ระบบดึงข้อมูลรายการจ่ายเงินผลประโยชน์ ที่มีเบี้ยประกันภัยค้างชำระ(งวดสุดท้าย) หรือลงทะเบียนชำระเบี้ยประกันภัยปีต่อ หรือลงทะเบียนเคสใหม่ ที่มีการอนุมัติตรวจจ่ายบัญชีจาก[หน้าจอรายละเอียด Support Booking](/pages/viewpage.action?pageId=1282507906) และต้องเป็นการโอนครั้งแรก โดยวันที่ปัจจุบันมากกว่าหรือเท่ากับวันที่โอนจ่ายเงินให้ลูกค้า
กรณียอดเงินสุทธิ = 0
- วันที่ปัจจุบันมากกว่าหรือเท่ากับวันที่โอนเงินผลประโยชน์ให้ลูกค้า(วันที่ Payment Date) และต้องยังไม่มีเลขที่รับฝาก
กรณียอดเงินสุทธิ > 0
- วันที่ปัจจุบันมากกว่าหรือเท่ากับวันที่โอนเงินผลประโยชน์ให้ลูกค้า(วันที่ Transfer Date) และต้องยังไม่มีเลขที่รับฝาก
**2. ตรวจสอบการลงทะเบียนเคสใหม่**
2.จากรายการข้อ(1) ตรวจสอบว่ามีรายการลงทะเบียนเคสใหม่หรือไม่
2.1. ถ้าพบว่ามีรายการลงทะเบียนเคสใหม่ อ้างอิงรายละเอียดจาก [Batch สำหรับตั้งรับฝากและบันทึกข้อมูลที่ระบบ Hydra](/pages/viewpage.action?pageId=905609304)
2.1.1. บันทึกรายการเข้าระบบรับฝาก
2.1.2. ทำการบันทึกรายการเข้าระบบ Auto Post
2.1.3. return เลขที่รับฝากกลับมาบันทึกที่ระบบ cenpay
2.2. ถ้าไม่พบรายการลงทะเบียนเคสใหม่ให้ทำต่อในข้อ(3)
**3. กระบวนการตั้งรับฝาก**
นำข้อมูลรายการชำระเบี้ยประกันปีต่อ หรือ เบี้ยประกันภัยค้างชำระ(เบี้ยงวดสุดท้าย) ที่ได้มาจากการทำขั้นตอน(2) มาทำรายการดังนี้

## Post-conditions

1. บันทึกรายการ รับฝากเบี้ยประกันภัยปีต่อ และ รับฝากเบี้ยเคสใหม่ บนระบบรับฝาก
2. บันทึกรายการชำระเบี้ยประกันปีต่อ,เบี้ยประกันภัยค้างชำระ และ ดอกเบี้ยเบี้ยประกันภัยค้างชำระ บนระบบใบเสร็จส่วนกลาง
**Remark**
1) กรณีที่มีการ rollback รายการกรณี error table receipt ให้ทำการเปลี่ยนสถานะเป็น cancel
2) [HERMES - insert ข้อมูลบัญชีขาตั้งรับฝาก](/pages/viewpage.action?pageId=258900363) ต้องกรอง channel ที่เป็น cenpay ออกเพื่อไม่ให้ลงบัญชีขาตั้งซ้ำ
3) [HERMES - 12. รายงานข้อมูลใบเสร็จที่ส่งพิมพ์ Outsource Printing](/pages/viewpage.action?pageId=250937732) --> ให้ dev ตรวจสอบเพิ่มไม่ให้มีเคส cenpay กรณีแสดงที่เป็นใบเสร็จเบี้ยรายการค้างชำระ(เบี้ยงวดสุดท้าย)
4) กรณีเบี้ยค้างชำระหรือจ่ายเบี้ยปีต่อ อุตสาหกรรมมากกว่า1งวด - - สามารถส่งยอดรวมไปยังใบเสร็จส่วนกลางได้เลย โดยที่ระบบใบเสร็จส่วนกลางจะทำการแตกงวดเอง
