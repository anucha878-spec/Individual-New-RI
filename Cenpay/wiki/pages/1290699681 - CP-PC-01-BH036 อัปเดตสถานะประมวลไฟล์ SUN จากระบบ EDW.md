# Objectives

- `เพื่ออัปเดตสถานะประมวลผลไฟล์ SUN ของรายการ Transaction ที่หน้าจอตรวจจ่าย บัญชี ([tx_payment_account](/display/RDSCPENH/tx_payment_account)) ให้เป็นปัจจุบันตรงตามสถานะที่ประมวลผลในระบบ EDW โดยอัตโนมัติ`
- `เพื่อให้ข้อมูลสถานะในระบบ Cenpay มีความถูกต้องและสอดคล้องกับระบบที่เกี่ยวข้อง`

# Process Overview

- `Batch Process นี้จะทำงานทุกๆ 5 นาที เพื่อกวาดรายการ Transaction ที่ผ่านการอนุมัติจ่ายแล้ว (account_approve_status เป็น 'ARR' 'APR') แต่สถานะการประมวลผลไฟล์ SUN (sun`_status`) ยังไม่เสร็จสมบูรณ์ (เป็นค่าว่าง หรือไม่ใช่ 'SUCCESS' หรือ 'EDW_POSTING') จากนั้น Batch จะเรียก Web Service [WS สำหรับดึง SUN Status กลับไป Stamp ระบบต้นทาง](/pages/viewpage.action?pageId=1284571237) ของระบบ EDW เพื่อสอบถามสถานะล่าสุด และนำมาตีความก่อนอัปเดตลงในตาราง [tx_payment_account](/display/RDSCPENH/tx_payment_account) เฉพาะในกรณีที่สถานะมีการเปลี่ยนแปลง`

# Pre-conditions

- `ต้องมีรายการ Transaction ในตาราง [tx_payment_account](/display/RDSCPENH/tx_payment_account) ที่มีเงื่อนไขดังนี้:`
  - `account_approve_status เป็น 'ARR' (อนุมัติ) และ`
  - `sun_status เป็นค่าว่าง หรือมีค่าอื่นที่ไม่ใช่ 'SUCCESS' และ 'EDW_POSTING'`
- `Batch สามารถเชื่อมต่อกับฐานข้อมูลของระบบ Cenpay` และสามารถเรียกใช้งาน `Web Service ของ EDW ได้`

# Process Description

1. `Batch กวาดข้อมูล Transaction ที่รอการอัปเดต`
  - `Actor: Batch Process (System)`
  - `Action:``Query` ข้อมูลจากตาราง `[tx_payment_account](/display/RDSCPENH/tx_payment_account)`เพื่อค้นหารายการตามเงื่อนไขที่กำหนด
  - `System: Cenpay`
  - `Data Involved:` `id`, `reference_number`, `account_approve_status``, sun_status`
  - ตัวอย่าง `SQL Statement` ดึงข้อมูล: <![CDATA[SELECT id, reference_number, account_approve_status, sun_status FROM tx_payment_account WHERE account_approve_status IN (&#39;APR&#39;) AND (sun_status IS NULL OR sun_status NOT IN (&#39;SUCCESS&#39;, &#39;EDW_POSTING&#39;));]]>
2. `เรียก [WS สำหรับดึง SUN Status กลับไป Stamp ระบบต้นทาง](/pages/viewpage.action?pageId=1284571237) เพื่อสอบถามสถานะจาก EDW`
  - `Actor: Batch Process (System)`
  - `Action: รวบรวม `fin_reference_no` ทั้งหมดที่ได้จากขั้นตอนที่ 1, แบ่งเป็นกลุ่ม (chunk) ขนาดไม่เกิน 20 รายการ และเรียก Web Service สำหรับแต่ละกลุ่ม`
  - `System: API Gateway / EDW`
  - `Input Body: เป็น JSON Array ของ `referenceNumber```Parameter Name``Description``Source Value (from [tx_payment_account](/display/RDSCPENH/tx_payment_account))``referenceNumber``เลขที่อ้างอิงฝ่ายการเงิน``reference_number`
3. `รับสถานะ SUN จาก EDW`
  - `Actor: Batch Process (System)`
  - `Action: ระบบรับผลลัพธ์ (JSON Array) จาก Web Service และสำหรับแต่ละรายการในผลลัพธ์ จะใช้ค่า `sunStatus` ที่ได้รับมาโดยตรง`
  - `System: Payment Management`
  - `Data Involved: `referenceNumber`, `sunStatus` (จาก WS)`
4. `Decision Point:` ตรวจสอบการเปลี่ยนแปลงของสถานะ
  - `Action:` สำหรับแต่ละ `referenceNumber` ที่ได้รับจาก`Web Service,` ระบบจะเปรียบเทียบค่า `sunStatus` ที่ได้รับมากับสถานะปัจจุบัน (`sun_status`) ของรายการนั้นในฐานข้อมูล
    - หาก `sunStatus` *ไม่เท่ากับ* `sun_status`:
      - ดำเนินการต่อใน ขั้นตอนที่ 5 เพื่ออัปเดตข้อมูล
    - หาก `sunStatus` *เท่ากับ* `sun_status`:
      - ข้ามการอัปเดตสำหรับรายการนี้ และไปทำรายการถัดไป
5. `อัปเดตสถานะในตาราง [tx_payment_account](/display/RDSCPENH/tx_payment_account)``Actor: Batch Process (System)``Action: อัปเดตฟิลด์ sun_status ในตาราง `tx_payment_dashboard` ด้วยค่า `sunStatus` ที่ได้รับจาก Web Service โดยตรง``System: Cenpay``Data Involved: reference_number, `sunStatus```ตัวอย่าง SQL Statement อัปเดตข้อมูล:` <![CDATA[UPDATE tx_payment_account SET sun_status = :sun_status_from_ws, -- ค่า sunStatus ที่ได้จาก WS โดยตรง edw_status = :processlogStatus, -- ค่า สถานะ Process Log updated_date = CURRENT_TIMESTAMP, updated_by = &#39;SYSTEM&#39; WHERE reference_number = :reference_no;]]>

# Post-conditions & Error Handling

- `Post-conditions (Success):`
  - `รายการ Transaction ใน tx_payment_account` ที่เข้าเงื่อนไข จะถูกอัปเดต `sun``_status` เป็นสถานะล่าสุดจากระบบ `EDW` (หากมีการเปลี่ยนแปลง)
  - `ระบบบันทึก Log การทำงานของ Batch Process สำเร็จ`
- `Post-conditions (Failure) & Error Handling:`
  - กรณีเรียก `Web Service ไม่สำเร็จ (e.g., HTTP 5xx, Timeout):`
    - `Action`: ระบบจะบันทึก `Log` ข้อผิดพลาดของทั้งกลุ่ม `(chunk)` ที่เรียกไม่สำเร็จ และข้ามไปทำงานกลุ่มถัดไป
  - กรณี`Web Service` ตอบกลับแต่ไม่พบข้อมูลของ `referenceNumber` ที่ส่งไป:
    - `Action:` ระบบจะบันทึก Log เป็น Warning ว่าไม่พบข้อมูลสำหรับ `referenceNumber` นั้นๆ และข้ามไป
  - `กรณี Database Update ไม่สำเร็จ:`
    - `Action: ระบบจะพยายาม Rollback การเปลี่ยนแปลงสำหรับรายการนั้น และบันทึก Log ข้อผิดพลาดร้ายแรง`
    - `Notification: ระบบจะส่งแจ้งเตือนไปยัง System Admin ทันที`
