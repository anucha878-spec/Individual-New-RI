# AC-001-FC-002_04 เงื่อนไขปุ่ม

| No | Component Type | Component Name | Default Value | Validation Rules/Action | Example | Remark |
|---|---|---|---|---|---|---|
| 1 | Button | Export CSV | Enable | เมื่อกดระบบจะทำการออกรายงาน CSV ตามหน้าจอ [AC-001-FC-004 ตัวอย่างหน้า CSV File เมื่อ Export ข้อมูล Support Booking](http://wiki.thaisamut.co.th/pages/viewpage.action?pageId=1275560533) |   |   |
| 2 | Button | บันทึกตรวจจ่าย | Enable | เมื่อกดปุ่ม ระบบจะตรวจสอบรายการที่บันทึก โดยกรณีที่เลือกไม่ถูกต้อง จะต้องระบุสาเหตุการไม่อนุมัติ กรณีที่ไม่ระบุสาเหตุการไม่อนุมัติอย่างน้อย 1 รายการ ระบบจะไม่อนุญาตให้บันทึกตรวจสอบกรณีที่มีการระบุการตรวจสอบที่ตรวจสอบผ่านระบบแล้ว ระบบจะทำการบันทึกรายการจ่ายให้สถานะตรวจสอบ เป็น ตรวจสอบเรียบร้อยแล้ว แล้ว Refresh หน้าจอ Popup กลับมาอีกครั้ง ถ้าเป็นกรณีที่ทุกรายการมีสถานะตรวจสอบเป็น ตรวจสอบเรียบร้อยแล้ว ระบบจะ Enable ปุ่มยืนยันตรวจสอบให้กด |   |   |
| 3 | Button | ยืนยันตรวจจ่าย | Disable | ระบบจะ Enable ปุ่มยืนยันตรวจสอบ ก็ต่อเมื่อสถานะตรวจสอบ ของทุกรายการเป็น ตรวจสอบเรียนร้อยแล้ว โดยผู้ใช้งานจะกดปุ่มยืนยันตรวจสอบ เพื่อให้ระบบบันทึกยืนยันการตรวจสอบรายการจ่ายว่าถูกต้องตามที่ได้ตรวจสอบโดยระบบจะทำการตรวจสอบรายละเอียดแต่ละรายการจ่าย ว่ามีรายการที่มีระบุข้อมูลไม่ถูกต้องหรือไม่กรณีที่มีข้อมูลไม่ถูกต้องระบบจะทำการบันทึกสถานะอนุมัติรายการของ Batch ปฎิบัติการดังกล่าวที่ [AC-001-FC-001 หน้าจอตรวจจ่ายบัญชี](/pages/viewpage.action?pageId=1272906266) เป็น ไม่อนุมัติตรวจจ่ายและสร้างรายการเดิมที่ใช้เลข Batch ปฎิบัติการเดิม เพื่อกลับสถานะทางบัญชี โดยมีค่าเป็นเงินลบ และให้สถานะอนุมัติรายการของ Batch ที่สร้างโดยระบบเป็น ไม่อนุมัติตรวจจ่าย (กลับรายการ)จากนั้นสร้าง Batch ปฎิบัติการใหม่ โดยอ้างอิง Batch ปฎิบัติการเดิม เฉพาะรายการที่มีข้อมูลถูกต้อง และบันทึกรายการทางบัญชีใหม่และปรับสถานะอนุมัติรายการของ Batch ที่สร้างใหม่เป็น รอตรวจจ่ายจากนั้นส่งรายการที่ไม่ถูกต้องกลับไปยังขั้นตอนตรวจจ่ายของทาง Oper โดยให้สถานะรายการจ่ายที่ไม่ถูกต้องเป็น ตรวจจ่ายไม่ผ่าน (ฝ่ายบัญชี) เพื่อให้ทาง Oper จัดการข้อมูลให้ถูกต้องและตั้งรายการจ่ายใหม่อีกครั้ง โดยแจ้งให้ทราบผ่านทาง [Email แจ้งรายการตรวจจ่ายไม่ผ่าน (ฝ่ายบัญชี) จากระบบ Centralize Payment](http://wiki.thaisamut.co.th/pages/viewpage.action?pageId=1278640261)กรณีที่ข้อมูลถูกต้องทั้งหมดระบบจะทำการบันทึกสถานะอนุมัติรายการของ Batch ปฎิบัติการดังกล่าวเป็น อนุมัติตรวจจ่ายระบบจะต้องบันทึกรายการจ่ายภายใต้ Batch ปฎิบัติการเข้าระบบ Payment Management พร้อมทั้ง Update สถานะการจ่าย ระดับ Transaction เป็น รออนุมัติจ่าย (ฝ่ายการเงิน)จากนั้น Update สถานะรายการ ของรายการธุรกรรมภายใต้ Batch ปฎิบัติการที่ Module เตรียมจ่าย ปฏิบัติการ : [PC-001-FC-001 หน้าจอรวมจ่าย](/pages/viewpage.action?pageId=1270252010) และ [PC-002-FC-001 หน้าจอตรวจสอบรายการเตรียมจ่าย](/pages/viewpage.action?pageId=1270252058) เป็น รอยืนยันทำจ่าย (ฝ่ายการเงิน) |   |   |
