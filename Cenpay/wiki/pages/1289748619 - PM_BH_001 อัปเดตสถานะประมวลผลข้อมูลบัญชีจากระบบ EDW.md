# Objectives

- `เพื่ออัปเดตสถานะของรายการ Transaction ที่หน้าจออนุมัติจ่ายและบันทึกบัญชี ([tx_payment_dashboard](/display/RDSCPENH/tx_payment_dashboard)) ให้เป็นปัจจุบันตรงตามสถานะที่ประมวลผลในระบบ EDW โดยอัตโนมัติ`
- `เพื่อให้ข้อมูลสถานะในระบบ Payment Management มีความถูกต้องและสอดคล้องกับระบบที่เกี่ยวข้อง`

# Process Overview

- `Batch Process นี้จะทำงานทุกๆ 5 นาที เพื่อกวาดรายการ Transaction ที่ยังคงมีสถานะ "EDW Processing" หรือ "ข้อมูลบัญชีไม่ถูกต้อง" และรายการยังไม่ถูกตัดรอบเช็คสถานะ EDW ในระบบ Payment Management จากนั้นจะเรียก Web Service [WS สำหรับดึงสถานะ ETL ตอนประมวลผลข้อมูลบัญชี](/pages/viewpage.action?pageId=1284309020) เพื่อสอบถามสถานะล่าสุด และนำค่าสถานะรวมถึงข้อมูลจากการประมวลผลบัญชีกลับมาอัปเดตในตาราง [tx_payment_dashboard](/display/RDSCPENH/tx_payment_dashboard) ของระบบ Payment Management เฉพาะในกรณีที่สถานะที่ได้มาใหม่แตกต่างจากสถานะเดิม`

# Pre-conditions

- `ต้องมีรายการ Transaction ในตาราง [tx_payment_dashboard](/display/RDSCPENH/tx_payment_dashboard) ที่มีสถานะ batch_status เป็น 'EDP' (EDW Processing) หรือ 'IAC' (ข้อมูลบัญชีไม่ถูกต้อง)`
- `Batch สามารถเชื่อมต่อกับฐานข้อมูลของระบบ Payment Management และสามารถเรียกใช้งาน Web Service ของ EDW ได้`

# Process Description

1. `Batch กวาดข้อมูล Transaction ที่รอการอัปเดต`
  - `Actor: Batch Process (System)`
  - `Action: Query ข้อมูลจากตาราง tx_payment_dashboard เพื่อค้นหารายการที่ batch_status มีค่าเป็น 'EDP' หรือ 'IAC' และ batch_cutoff_time เป็น null หรือเป็น 'N'`
  - `System: Payment Management DB`
  - `Data Involved: id, batch_status, edw_system_key`
  - `ตัวอย่าง SQL Statement ดึงข้อมูล:` <![CDATA[SELECT id, batch_status, edw_system_key FROM tx_payment_dashboard WHERE batch_status in (&#39;EDP&#39;,&#39;IAC&#39;) AND (batch_cutoff_time is null or batch_cutoff_time = &#39;N&#39;); ]]>
2. `เรียก [WS สำหรับดึงสถานะ ETL ตอนประมวลผลข้อมูลบัญชี](/pages/viewpage.action?pageId=1284309020) เพื่อสอบถามสถานะจาก EDW`
  - `Actor: Batch Process (System)`
  - `Action: สำหรับทุกรายการที่ได้จากขั้นตอนที่ 1, ระบบจะทำการเรียก Web Service ของ EDW เพื่อดึงสถานะล่าสุด`
  - `System: API Gateway / EDW`
  - `Data Involved: id, edw_system_key, fin_reference_no, edw_process_log_id`
  - `Input Parameter Mapping:``Parameter Name``Description``Source Value (from tx_payment_dashboard)``systemName``ชื่อระบบต้นทาง``'PAYMENTMG' (ค่าคงที่)``systemKey``Key สำหรับ ETL``edw_system_key`
3. `รับและตีความสถานะจาก EDW`
  - `Actor: Batch Process (System)`
  - `Action: ระบบรับค่า `status` ที่ได้จาก Output ของ Web Service และทำการตีความ (Map) เป็นสถานะของฝั่ง Payment Management`
  - `System: Payment Management`
  - `Data Involved: `edw_status` (จาก WS), `mapped_paym_status``
  - `Status Mapping Logic:``EDW Status``Mapped Paym Status``LANDING, WAITETL, PREPROCESS_ETL, EXTRACT_IMPORT, TRANSFORM, JOINAGG, RECONCILE, ACCAPPROVED, SENDTOADW``EDP (EDW Processing)``WAIT_SENDTOADW``PEA (Pending Approval)``ERROR, RECONCILE_FAILED``IAC (Invalid Account)`หมายเหตุ: สถานะที่อยู่นอกเหนือ `edw_status` `ให้ข้ามการอัปเดตสำหรับรายการนี้ และไปทำรายการถัดไป`
4. Decision Point: ตรวจสอบการเปลี่ยนแปลงของสถานะ
  1. หาก `mapped_paym_status` *ไม่เท่ากับ* `current_status`: ดำเนินการต่อใน ขั้นตอนที่ 5 เพื่ออัปเดตข้อมูล
  2. หาก `mapped_paym_status` *เท่ากับ* `current_status`: ข้ามการอัปเดตสำหรับรายการนี้ และไปทำรายการถัดไป (กรณีนี้รวมถึงรายการที่ใน Payment Management มีสถานะเป็น 'EDP' อยู่แล้ว และได้รับสถานะกลุ่ม Processing อื่นๆ จาก EDW มาอีกครั้ง)
5. `อัปเดตสถานะในตาราง tx_payment_dashboard`
  1. `Actor: Batch Process (System)`
  2. `Action: อัปเดตฟิลด์ batch_status และฟิลด์ที่เกี่ยวข้องในตาราง tx_payment_dashboard`
  3. `System: Payment Management DB`
  4. `Data Involved: id, mapped_paym_status, txAdwpcProcessLogId, referenceNumber, dashboardId`
  5. `ตัวอย่าง SQL Statement อัปเดตข้อมูล:` <![CDATA[UPDATE tx_payment_dashboard SET batch_status = :mapped_paym_status, edw_process_log_id = :txAdwpcProcessLogId fin_reference_no = :referenceNumber dashboard_id = :dashboardId batch_cutoff_time = &#39;Y&#39; updated_date = CURRENT_TIMESTAMP, updated_by = &#39;SYSTEM&#39; WHERE id = :record_id;]]>
6. บันทึกข้อมูลที่ตาราง [lg_batch_process](/display/RDSCPENH/lg_batch_process)
  1. batch_code = PM_BH_001
  2. กรณี Run Batch Manual จากหน้าจอ [FS-09-01 หน้าจอ Batch Manual Process](/pages/viewpage.action?pageId=1290404320) ให้ข้ามการบันทึกข้อมูลนี้ FieldDescriptionMapping databatch_idรหัส BatchAuto generatebatch_codeรหัส BatchBatch Codestatusสถานะการ Run BatchF - กรณี Batch Failerror_messageข้อความกรณี Run Batch Failบันทึกข้อความกรณีมี Error ที่ Run Batch Processtypeประเภทการ Run BatchA - Autocreated_datedวันที่สร้างบันทึกวันและเวลาปัจจุบันcreated_byผู้สร้างบันทึก System
    - Insert ข้อมูลที่ตาราง [lg_batch_process](/display/RDSCPENH/lg_batch_process)

# Post-conditions & Error Handling

- `Post-conditions (Success):`
  - รายการ Transaction ใน tx_payment_dashboard ที่เคยมีสถานะเป็น 'EDP' หรือ 'IAC' และยังไม่ถูกตัดรอบตรวจสอบสถานะ EDW จะถูกอัปเดตเป็นสถานะล่าสุดจากระบบ EDW (หากมีการเปลี่ยนแปลง)
  - ระบบบันทึก Log การทำงานของ Batch Process สำเร็จ
- `Post-conditions (Failure) & Error Handling:`
  - `กรณีเรียก Web Service ไม่สำเร็จ (e.g., Timeout, Connection Error):`
    - Action: ระบบจะบันทึก Log ข้อผิดพลาดพร้อมระบุ id ของรายการที่ไม่สำเร็จ, ข้ามการอัปเดตสำหรับรายการนั้น และดำเนินการกับรายการถัดไป
    - Notification: หากเกิดข้อผิดพลาดติดต่อกันเกิน 3 ครั้ง, ระบบจะส่งแจ้งเตือนไปยัง System Admin
  - `กรณี Database Update ไม่สำเร็จ:`
    - Action: ระบบจะพยายาม Rollback การเปลี่ยนแปลงสำหรับรายการนั้น และบันทึก Log ข้อผิดพลาดร้ายแรง
    - Notification: ระบบจะส่งแจ้งเตือนไปยัง System Admin ทันที
  - `กรณีได้รับสถานะจาก EDW ที่ไม่รู้จัก (ไม่อยู่ใน image.png):`
    - `Action: ระบบจะไม่ทำการอัปเดต, บันทึก Log เป็น Warning พร้อมระบุ id และค่าสถานะที่ไม่รู้จัก`
    - `Notification: ไม่มีการแจ้งเตือน แต่ต้องมีการ Monitor Log ดังกล่าวเป็นประจำ`
