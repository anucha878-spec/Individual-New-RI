ส่วน A · กติกา

5 กฎที่ต้องจำก่อนกดปุ่มใด ๆ

1 · ขาจ่ายกับขารับเดินคนละทาง

ขาจ่าย (net_amount < 0) = ออกเลขอ้างอิง + ส่ง PayM
ขารับ (ยอดบวก) = ไม่ส่ง PayM ไม่มีเลขอ้างอิง โดยดีไซน์ ไม่ใช่บั๊ก

2 · เลขอ้างอิงออกใหม่ทุกครั้งที่ส่ง

RI-TB-YYYYMMDD-00001 · running ที่ tx_running_no key H_RI_TB/YYYYMMDD
ส่งใหม่ = ทับเลขเดิม และ PayM ทิ้งรายการเก่า

3 · จุดออกเลขอยู่ที่ 2 ปุ่มนี้เท่านั้น

ปุ่ม "พิจารณาอนุมัติข้อมูลเข้า EDW" · ปุ่มบน คอลัมน์สถานะฝ่ายการเงิน (ส่งซ้ำ)
ปุ่ม "พิจารณาอนุมัติเข้าฝ่ายการเงิน" ถูกตัดออกแล้ว

4 · การส่งมี WS 2 ตัวเรียงกัน

WS1 บันทึกรายการจ่าย → WS2 บันทึกประมาณการจ่าย
ติดที่ WS2 หมายเหตุต้องเป็น "ไม่สามารถบันทึกรายการประมาณการจ่ายได้" และรายการนั้นต้องมีเลขอ้างอิงแล้ว

5 · ชื่อคอลัมน์หลอก

เลขเก็บที่ tx_ri_actual_offset.batch_oper_no แต่ส่งเข้า PayM เป็น operRefNo ระดับรายการ ไม่ใช่ batchOperNo ระดับ Batch · ถ้า oper_ref_no ฝั่ง PayM ไม่ตรงทุกตัวอักษร batch EDW_BH_054 จะหาสถานะไม่เจอทุกรอบและยิงอีเมลแจ้ง IT ทุก 10 นาที

ส่วน B · การตั้งค่า

ผังบัญชีผูกด้วย event_code

ตั้งค่าที่ cf_event_code (ผังบัญชี) และ cf_adwpc_query_model (การบันทึกจำนวนเงินในผัง)

event_codeกลุ่มธุรกรรมเกี่ยวกับ UAT รอบนี้
PM_FIN_02จ่ายเงินตัวหลัก รายการจ่ายประกันภัยต่อที่อนุมัติจ่ายแล้ว
PM_FIN_01รายการไม่ผ่านตรวจสอบต้องทดสอบ คู่กับเคส reject ของฝ่ายการเงิน (สถานะ 15)
PM_FIN_03ค่าธรรมเนียมธนาคารยังไม่มีเคสฝั่ง RI ต้องตกลงว่าอยู่ในรอบนี้หรือไม่

ต้องยืนยันก่อนวันที่ 15 ก.ย.

  • ผัง cf_event_code / cf_adwpc_query_model ถูก config สำหรับธุรกรรม ประกันภัยต่อ แล้วหรือยัง
  • รายการ RI ใช้ PM_FIN_02 ตัวเดียว หรือมีผังเฉพาะของ RI
  • ผูกบัญชีบริษัท (Bank Account) กับธุรกรรม RI เรียบร้อยแล้วหรือไม่

ถ้าข้อใดยังไม่พร้อม บัญชีจะไม่ลงหรือลงผิดผัง แล้วจะแยกไม่ออกว่าเป็นบั๊กหรือ config — ยังไม่มีเคสทดสอบข้อนี้ในชุด SIT

  2. อนุมัติใบขารับที่ SD007 → นับแถวใหม่ — ต้องเพิ่ม
  3. อนุมัติใบขาจ่ายที่ SD007 → นับแถวใหม่ — ต้องไม่เพิ่ม (บัญชีขาจ่ายยังไม่เกิด)
  4. ไปฝั่งการเงิน — ตรวจ → อนุมัติ → อนุมัติจ่ายและบันทึกบัญชี
  5. กลับมาที่ EDW — เปิดเมนูตรวจสอบรายการ EDW: ต้องเห็นรายการจ่ายพร้อมคู่บัญชีของ PM_FIN_02
  6. ตรวจคู่บัญชี ใน tx_adw_double_entry_detail — Dr เท่ากับ Cr · ผังตรงกับที่ตกลง · ยอดตรงกับที่จ่ายจริง
  7. ตรวจ File SUN — ไฟล์ออกที่ path ที่กำหนด · ยอดในไฟล์ตรงกับคู่บัญชี
  8. เคส reject — ให้การเงิน "ไม่ผ่านการตรวจสอบ" 1 ใบ → สถานะกลับมาเป็น 15 บน SD007 และบัญชีเดินตาม PM_FIN_01
  9. เคสส่งซ้ำ — กดส่งซ้ำใบที่ reject → ยืนยันว่าไม่เกิดคู่บัญชีซ้ำ จากรายการเดิม

ข้อ 9 คือจุดที่อันตรายที่สุดของรอบนี้ — ส่งซ้ำแล้วบัญชีลงสองรอบคือความเสียหายที่แก้ย้อนหลังยากที่สุด

เวลาเจอปัญหา ให้แนบ 5 อย่างนี้ทุกครั้ง

  1. เลขอ้างอิง RI-TB-… และ tx_ri_actual_offset_id ของใบที่ทำ
  2. เวลาที่กด (ระบุนาที) และ user ที่ใช้
  3. สถานะรายการ + สถานะฝ่ายการเงิน ก่อนและหลัง
  4. ภาพหน้าจอที่เห็นปัญหา รวมข้อความ error เต็ม ๆ
  5. ทำผ่านหน้าจอ หรือมีการแก้ข้อมูลด้วย script ระหว่างทาง

ข้อ 5 สำคัญกว่าที่คิด — ในรอบ SIT มีหลายเคสที่ผ่านเพราะจัดข้อมูลด้วย script แล้วพอเดิน flow จริงกลับพัง

สรุป

จำ 5 ข้อนี้พอ

1 · ขาจ่ายไป PayM ขารับลง GL

สองขาเดินคนละทางตั้งแต่ต้น อย่าเอาเกณฑ์เดียวกันไปตรวจทั้งคู่

2 · เลขอ้างอิงออกใหม่ทุกครั้งที่ส่ง

ยกเว้นการส่งซ้ำจากสถานะ 21 ที่ต้องใช้เลขเดิม

3 · บัญชีเกิด 2 จังหวะ

ขารับที่ EDW ตอนอนุมัติ · ขาจ่ายที่ PayM ตอนอนุมัติจ่ายและบันทึกบัญชี แล้วเด้งกลับมา EDW + File SUN

4 · นับแถวบัญชีก่อนกดทุกครั้ง

เป็นวิธีเดียวที่จับ "บัญชีลงซ้ำ" ได้ทันที

5 · เข้ารอบนี้ด้วยของค้าง 2 ใบ

#99867 Offset ใหม่ไม่รับช่วงค่า (เลี่ยงเคสนี้ก่อน) · #99492 อีเมลแจ้งเตือนยังไม่ออก (ต้องเปิดหน้าจอดูเอง) · และ 2 เคสยอดเงินซ้ำ/แถวผี ที่ยังไม่เคยทดสอบ
